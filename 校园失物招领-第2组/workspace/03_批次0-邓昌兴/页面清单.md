**优先级定义**

- **P0**：演示脚本必经页面，缺一页流程就断。

## 2. A 学生端（金道轩）—— `/student`

| # | 路由 | 页面 | 这个页面干什么 | 关键操作 | 依赖接口 | 优先级 |
|---|---|---|---|---|---|---|
| A1 | `/student/home` | 失物招领大厅 | 浏览已审核通过的招领 / 寻物信息，是学生进入系统的首页 | 关键词搜索、按分类/地点/类型/时间筛选、分页、进入详情 | `GET /items` | P0 |
| A2 | `/student/detail/:id` | 物品详情 | 看图片、描述、拾取/丢失地点与时间、发布人（脱敏）、认领须知 | 发起认领、举报、返回 | `GET /items/{id}` | P0 |
| A3 | `/student/publish` | 发布信息 | 发布「我捡到了」或「我丢了」的信息，提交后进入待审核 | 选类型、传图、填分类/地点/时间/描述、提交 | `POST /items` | P0 |
| A4 | `/student/my-items` | 我的发布 | 管理自己发布的信息及审核状态 | 查看状态、编辑、下架、查看该物品的认领申请 | `GET /items/my`、`PUT /items/{id}` | P0 |
| A5 | `/student/claim-apply/:itemId` | 认领申请 | 填写物品特征和凭证，证明物品是自己的 | 填特征描述、上传凭证图、留联系方式、提交 | `POST /claims` | P0 |
| A6 | `/student/my-claims` | 我的申请 | 跟踪自己认领申请的审核进度 | 查看状态与审核意见、撤销申请 | `GET /claims/my` | P0 |
| A7 | `/student/notices` | 消息通知 | 接收审核结果、认领进度通知 | 列表、标记已读、跳转对应详情 | `GET /notices` | P1 |
| A8 | `/student/profile` | 个人中心 | 维护个人资料与密码 | 改昵称/头像/手机号、改密码 | `GET/PUT /users/me` | P1 |

**学生端主流程**：`home → detail → claim-apply → 等待审核 → my-claims 看结果 → 归还`

## 3. B 审核端（李子研）—— `/audit`

| # | 路由 | 页面 | 这个页面干什么 | 关键操作 | 依赖接口 | 优先级 |
|---|---|---|---|---|---|---|
| B1 | `/audit/workbench` | 审核工作台 | 审核员上班第一屏：待办数量 + 快捷入口 | 看待审发布数/待审认领数/今日已审数，点击跳转 | `GET /audit/stats` | P0 |
| B2 | `/audit/publish-review` | 发布审核 | 审核学生提交的招领 / 寻物信息是否真实、合规 | 查看详情与图片、通过、驳回并填写原因 | `GET /audit/items/pending`、`POST /audit/items/{id}/approve`、`POST /audit/items/{id}/reject` | P0 |
| B3 | `/audit/claim-review` | 认领审核 | 核心页面：核验认领人身份与凭证，决定是否归还 | 对比物品信息与申请描述、查看凭证、通过、驳回、要求补充材料 | `GET /audit/claims/pending`、`POST /audit/claims/{id}/approve`、`POST /audit/claims/{id}/reject` | P0 |
| B4 | `/audit/return-register` | 归还登记 | 线下交接完成后登记，闭环状态 | 选择已通过的认领单、上传交接凭证、确认归还 | `GET /claims?status=APPROVED`、`POST /claims/{id}/return` | P0 |
| B5 | `/audit/records` | 审核记录 | 查询本人/全部历史审核，便于追溯 | 按类型/结果/时间筛选、查看详情 | `GET /audit/records` | P1 |
| B6 | `/audit/profile` | 个人中心 | 审核员资料与密码 | 改资料、改密码 | `GET/PUT /users/me` | P1 |

**审核端主流程**：`workbench → publish-review（先让物品上架）→ claim-review（审核认领）→ return-register（登记归还）`

## 4. C 后台端（欧阳昊天）—— `/admin`

| # | 路由 | 页面 | 这个页面干什么 | 关键操作 | 依赖接口 | 优先级 |
|---|---|---|---|---|---|---|
| C1 | `/admin/dashboard` | 数据看板 | 平台整体运行情况，答辩时最出效果的一屏 | 物品总数/待审数/认领成功率、近 7 天趋势图 | `GET /admin/stats` | P0（图 P1） |
| C2 | `/admin/users` | 用户管理 | 管理学生与审核员账号 | 查询、新增审核员、启用/禁用、重置密码、分配角色 | `GET/POST/PUT /admin/users` | P0 |
| C3 | `/admin/categories` | 分类管理 | 维护物品分类（证件、电子产品、书籍…） | 增删改查、排序、启用/停用 | `GET/POST/PUT/DELETE /admin/categories` | P0 |
| C4 | `/admin/items` | 物品管理 | 全量查看与干预物品信息 | 查询、查看详情、强制下架、删除 | `GET /admin/items`、`PUT /admin/items/{id}` | P1 |
| C5 | `/admin/claims` | 认领管理 | 全量认领单与流转记录 | 查询、查看流转详情、异常处理 | `GET /admin/claims` | P1 |
| C6 | `/admin/notices` | 公告管理 | 发布系统公告 | 新增、编辑、删除、置顶 | `GET/POST/PUT/DELETE /admin/notices` | P1 |
| C7 | `/admin/logs` | 操作日志 | 审计管理员关键操作 | 按人/类型/时间查询 | `GET /admin/logs` | P1 |
| C8 | `/admin/settings` | 系统设置 | 认领时限、联系方式等基础参数 | 修改并保存 | `GET/PUT /admin/settings` | P2 |
| C9 | `/admin/profile` | 个人中心 | 管理员资料与密码 | 改资料、改密码 | `GET/PUT /users/me` | P1 |

> C4/C5 与 B2/B3 的区别：审核端**只处理待办**，后台端**全量查询与兜底干预**，权限与页面都要分开，答辩时要能讲清这个边界。

## 5. 页面流转图

```
                    ┌──────────┐
                    │  /login  │
                    └────┬─────┘
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
   ┌────────────┐  ┌────────────┐  ┌────────────┐
   │ 学生端      │  │ 审核端      │  │ 后台端      │
   │ /student   │  │ /audit     │  │ /admin     │
   └─────┬──────┘  └─────┬──────┘  └─────┬──────┘
         │               │               │
   home → detail    workbench      dashboard
         │               │               │
    publish          publish-review   users / categories
         │               │               │
    my-items         claim-review      items / claims
         │               │               │
   claim-apply      return-register   notices / logs
         │               │
    my-claims ←──────────┘（审核结果回流）
         │
      notices / profile
```

**端到端主链路（答辩必演）**

```
学生 publish → 审核员 publish-review 通过 → 学生 home 看到 → 学生 claim-apply
→ 审核员 claim-review 通过 → 审核员 return-register → 学生 my-claims 显示已归还
```

**组件开发规范**

1. 组件必须 `<script setup lang="ts">`，Props 用 `defineProps<...>()` 类型声明，不用运行时对象写法。
2. 组件不直接调接口；数据由页面传入（`StatCard`/`ChartCard` 也由页面取数）。
3. 组件不写死业务文案，文案走 Props 或插槽。
4. 公共组件改动由负责人统一改，其他人不要在页面里复制粘贴改一份。
