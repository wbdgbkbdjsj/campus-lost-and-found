## 2 编号空间总表（全组最容易出错的一节）

| 编号空间 | 含义 | 格式 | 权威出处 | 示例 | 禁止混写 |
|---|---|---|---|---|---|
| `FR-xx` | 功能需求 | 两位数字 | 《需求说明书》§3 | `FR-09` 身份核验 | 不写成「需求 9」 |
| `UC-xx` | 用例 | **两位数字补零** | 《用例图》§2 | `UC-11` | 契约 §7 的 `UC-1` 是简写，不采用 |
| `#N` | 接口编号 | `#` + 数字 | 契约 v1 §3 | `#19` 身份核验 | 不写 `API-19`、不写路径代替编号 |
| `TC-xxx` | 测试用例 | 模块前缀 + 序号 | 《测试用例表》 | `TC-CLAIM-01`、`TC-REV-05` | 不与冒烟 24 项混算 |
| `步 N` | 演示步骤 | 「步」+ 数字 | 《演示脚本-v0.md》§2（15 步） | `步 12` 身份核验 | **不写 `D-12`**（见下方历史坑） |
| `DEP-x` | 假定与依赖 | `DEP-` + 一位数字 | 《需求说明书》§2.5 | `DEP-1` 契约冻结 | 与演示步号互不相干 |
| `BR-xx` / `SEC-xx` | 业务规则 / 安全需求 | 两位数字 | 《需求说明书》§3 | `BR-01` 禁止自动放行 | — |
| `I1`–`I7` | 状态机不变量 | `I` + 数字 | 契约 v1 §5.3 | **I7** 交接前须核验 | — |
| `R1`–`R8` | 风险项 | `R` + 数字 | 《总体设计报告》§9 | `R3` 契约被改 | 与情况记录表 `R-xx` 不同源 |
| `DL-xx` / `D-xx` / `R-xx` | 交付登记 / 决议 / 风险 | 按原表 | 《情况记录表》（欧阳昊天） | `DL-10` | 仅用于过程记录，不进技术文档 |
| `图 x-y` / `表 x-y` | 图题 / 表题 | 章号-序号 | 各文档 | `图 3-1`、`表 5-2` | 见 §4「只对编号图表强制」 |
| 文档编号 | 文档标识 | 三字母 + 版本 | 各文档头部 | `SRS-v1` `GDD-v1` `GLO-v1` `UC-v1` `CONV-v1` | 不重复分配 |

**三个已经踩过的坑，别再踩：**

| 坑 | 结论 |
|---|---|
| `D-xx` 曾同时表示「演示步」和「假定依赖」 | 假定依赖统一改 `DEP-x`，演示统一「步 N」，§2.5 已加消歧说明 |

## 3 命名与术语（细则见《术语表-v1》，此处只列最易错的）

| 项 | 唯一写法 |
|---|---|
| 三角色 | `student` / `reviewer` / `super_admin`；`admin`、`user`、`auditor` 一律废弃 |
| 三端 | A 学生端 / B 审核端 / C 后台管理端，**单工程 + RBAC**，不是三个工程 |
| 表 | 9 张：`user` `category` `location` `lost_item` `found_item` `claim` `review_record` `notification` `audit_log` |
| 状态 | 认领单 8 态 / 物品 5 态，英文大写下划线，界面与 PPT 上「状态码 + 中文名」并列 |
| **主流程顺序** | 提交 → 接单 → **审核通过(#20)** → **身份核验(#19，`APPROVED` 自环、不改状态、写 `VERIFY` 流水)** → 交接(#23，I7 前置) |
| 双轨技术栈 | 正式方案 Vue3 + Spring Boot 3 + MyBatis-Plus + MySQL 8 + Nginx（骨架见 `03_批次0-邓昌兴/lost-found-server/`，业务接口未实现）；界面见 `lost-found-web/`（25 页 Vue3 骨架，23 页占位）；`05_源码/` 为**业务唯一可跑**的同构 FastAPI 原型。三者构件一一对应。**组长 11-05 裁决：演示链路 = `src/lost-found-prototype/` 零构建单页 + FastAPI 后端**，Vue 工程降为正式方案骨架、不再联调 |

> 术语表里「禁用同义词」约束的是**正式文档正文**；代码变量、数据库字段、口头讲解用简称不受此限（例如代码里 `claim`、口语说「认领单」都可以）。

## 4 文档格式约定（可执行的最低要求）

| 项 | 约定 |
|---|---|
| 编码 | UTF-8；Git 自动转 CRLF 不影响内容 |
| 图 | 一律 Mermaid 代码块，**不交图片文件**；导出 Word/PDF 后必须人工翻一遍确认图渲染出来 |
| 图题 / 表题 | `图 x-y` / `表 x-y` **只对正文中有编号、被正文引用的图表强制**（如「见图 3-1」）；行内小表、参数表可省表题 —— 此前写「表题一律」但没执行，现按此收敛 |
| 引用 | 其他材料写《文件名》§章节号；接口写 `#N`；演示写「步 N」；契约写《api-contract-v1.md》§x |
| 定稿禁用 | 定稿文档不得出现 `[待补]`、`TODO`、`待定`、`略`；确有未完成项须在正文显式写出「范围外」并说明原因 |
| 状态栏 | 每份文档头部必须有「版本 / 状态 / 依据」三行，**现行与否看状态栏，不看文件名里的 v0/v1** |
| 版本记录 | 每次定稿填文档末尾变更记录表：版本、日期、修改人、说明；**仅格式 / 引用调整不升版本号，但须留痕**（本轮各文档即以「v1 修订」记） |
