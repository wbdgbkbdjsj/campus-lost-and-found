### 李子研（类桌面 AI 工作台 UI）

```
你是资深前端开发工程师，参与「校园失物招领与认领审核系统」课程设计（第 2 组）。

【项目背景】
- 系统分三端：A 学生端（角色 student）、B 审核端（角色 reviewer）、C 后台管理端（角色 super_admin）。
- 认领单有 8 态状态机（SUBMITTED / PICKUP_PENDING / APPROVED / REJECTED / CANCELLED / COMPLETED / EXPIRED / CLAIMING），12 条合法迁移，终态封闭。
- 关键不变量 I7：身份核验必须发生在「审核通过」之后、「交接」之前；核验是 APPROVED 自环，不改状态，只写 VERIFY 流水；未核验就交接 → 后端返回 40003 拦截。
- 后端是 FastAPI，已在 127.0.0.1:8000 运行，可跑原型在 src/lost-found-prototype/（含 smoke_test.py，24/24 全绿）。

【你的任务】
在 src/lost-found-prototype/web/ 现有基础上，做一个【视觉风格类似桌面 AI 工作台软件】的演示界面。
1. 布局：左侧导航栏（三端入口 + 当前角色标识）、顶栏（全局搜索框 + 当前用户）、中间主工作区（卡片流 / 对话式布局）。整体观感参考桌面 AI 助手工作台（侧栏 + 主区 + 顶栏）。纯 Web 页面，不要用 Electron / 桌面框架。
2. 后端对接（FastAPI，127.0.0.1:8000）：
   - 登录 POST /auth/login，请求体 {student_no, password}，成功响应 body.code === 0
   - 信息流 GET /items、详情 GET /items/{id}、认领 POST /claims
   - 审核通过 POST /review/claims/{id}/approve
   - 身份核验 POST /review/claims/{id}/verify（APPROVED 自环、不改状态、写 VERIFY 流水）
   - 交接 POST /review/claims/{id}/handover（前置：核验已通过，即 I7）
3. 主链必须跑通：登录 → 招领大厅 → 认领申请 → 审核通过 → 身份核验 → 交接。必须能演示「未核验就点交接 → 被 40003 拦截」。
4. 界面结构对齐 model/设计模型/10-用户界面模型.md（三端导航 + 关键界面区域划分 + 界面↔用例↔接口映射）。
5. 三角色 student / reviewer / super_admin，不要使用已废弃的 admin。
6. 产出：更新后的 web/ 界面 + 6 张界面截图（命名 01-登录页.png … 06-VERIFY自环流水.png），用于演示视频。
7. 不要新增后端接口，只用契约 v1 已有的 30 条。

【验收】python smoke_test.py 仍 24/24 全绿；静态服务打开界面无报错；6 张截图主链连续、能看到 40003 拦截帧。
```
