```
你是本组的后端设计负责人。请为「校园失物招领与认领审核系统」产出一份《数据字典与接口契约 v0》，供 5 人小组并行开发使用，输出为一份 Markdown 文档。

【项目背景】
大学生软件工程课程设计，单工程 + RBAC 三端，前后端分离，Vue3 + Spring Boot + MySQL。
- A 学生端：注册登录、发布失物登记/招领登记（含图片）、按分类/地点/时间搜索筛选、查看物品详情、提交认领申请、查看我的申请与消息通知
- B 审核端：认领申请列表、身份核验、审核通过/驳回、物品状态流转、争议处理、操作留痕
- C 后台管理端：用户管理、分类/地点字典维护、公告、数据统计看板、操作日志查询、Excel 导出

【核心主流程】
发布登记 → 搜索浏览 → 提交认领申请 → 管理员身份核验 → 审核通过/驳回 → 线下归还确认 → 物品归档
物品状态：待认领 / 审核中 / 已归还 / 已归档（驳回回到待认领）
角色：学生 / 审核员 / 超级管理员

【必须输出的 6 块内容】
1. 术语与枚举字典：所有业务名词、状态枚举、角色枚举，给出统一中文名 + 英文字段值
2. 数据库表结构：不少于 8 张表（user、item、claim、audit_record、category、location、notice、operation_log 等），逐个用表格列出 字段名 / 类型 / 主键外键 / 非空 / 默认值 / 中文说明

【硬性约束】
- 术语全文严格一致，禁止同义词混用；表名/字段名 snake_case，接口路径 REST 风格

- 表结构和接口要能直接被前端/测试/文档复用，字段不要写「待定」「略」
- 中文输出，标题层级清晰，表格完整

先输出完整文档，不要解释过程。
```
