## 6 答辩三问·标准答法（务必本人过一遍）

**Q1｜「文档写 Spring Boot + MySQL，怎么演示跑的是 Python + SQLite？」**
> 三块源码各司其职：正式方案 Vue3 + Spring Boot 3 + MySQL 8 的工程骨架已经搭好（可编译，见 `lost-found-server/`），Vue 界面 25 页也已构建通过（见 `lost-found-web/`）；而业务接口最先跑通的是同构 FastAPI 原型 `05_源码/`，它把最难的审核状态流和 I7 防冒领规则验证透了，留下 24 项两次复现的测试证据。现场演示用的是**已跑通的零构建单页 + FastAPI 业务后端**（`src/lost-found-prototype/`，24 项冒烟两次复现全绿、浏览器端到端 15/15 通过）；Vue3 工程化前端与 Spring Boot 后端是正式技术方案骨架（可构建 / 可编译），按契约一一对应、可平移，本轮**不宣称其业务层已实现**。Spring Boot 侧构件一一对应（service↔review-module、state_machine↔状态机、main↔Controller、models↔实体），属于工程化平移范围，不是两套设计、也不是没做。

**Q2｜「A/B/C 三端都做完了吗？C 端呢？」**
> 三端界面都做出来了（学生端 8 页、审核端 6 页、后台端 9 页），业务上跑通的是 A 端基础接口 + B 端审核状态流 —— 这是课题「认领审核」的核心；C 端 #25–30 的接口在契约里定义完整，原型目前只做到 `super_admin` 登录，页面是占位/只读，没有造假数据。我们选择先把核心状态机与防冒领规则做实做透，而不是三端都做半成品。

**Q3｜「代码规模够吗？指导书要求 1 万行左右。」**
> 如实说：**目前还不够**。去重后实测四块源码合计约 4785 行（FastAPI 1242 + Vue 1756 + Spring Boot 666 + 零构建演示前端 1121，已排除构建产物、vendor 与重复副本），按表 4 落在「少于 6000 行」档，差约 1200 行，这是我们要补的短板，不虚报。但已跑通的部分是实的：9 张表、24 条路由、8 态 12 迁移、I1–I7 全部关键不变量，24 项断言两次独立复跑全绿。补齐路径是明确的、且和别的要求重合：把 Vue 主链 8 页从占位写成真实页面（同时交「软件界面原型」）、Spring Boot 补 Controller/ServiceImpl、C 端 #25–30 落地、三层测试代码入库。我们选择把行数涨在真实功能上，而不是灌重复代码凑数。
