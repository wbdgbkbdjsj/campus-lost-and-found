## 0. 使用约定

1. **一词一义**：一个概念只保留一个中文名，其余叫法一律进第 8 节禁用表。
2. **中文名优先**：正文、界面、PPT 用中文名；代码、数据库、接口用英文代码名。
3. **代码名规范**：表名/字段名 `snake_case`，接口路径 `/api` 前缀 + REST 风格，状态枚举值大写下划线（**待契约确认**）。
4. **图的规范**：所有图用 Mermaid 代码块，不生成图片文件。
5. **变更规则**：契约发出后要改，先在群里说一声再改，并记入情况记录表（欧阳昊天）。偷偷改字段名会让三端代码和测试用例一起崩。
6. **版本规则**：`xxx-v0.md` 为初版，对齐定稿后去后缀或改 `v1`；旧版移入归档，不直接覆盖。

## 1. 角色与端

| 中文名 | 英文代码名 | 定义 | 归属端 | 备注 |
|---|---|---|---|---|
| 学生 | `student` | 在校注册用户，可发布登记、搜索物品、提交认领申请 | A 学生端 | 契约角色枚举之一 |
| 拾获人 | `finder` | 拾到物品并发布招领登记的学生，是「学生」在同一流程中的**场景称呼**，不新增角色 | A 学生端 | 仅用于叙述，数据库不单设角色 |

| 超级管理员 | `admin` | 维护用户、分类/地点字典、公告、统计看板、操作日志、Excel 导出 | C 后台管理端 | 契约角色枚举之一 |
| A 学生端 | `portal` / A | 面向学生的前台，注册登录、登记、搜索、认领、消息 | — | 三端统一技术栈内分端 |
| B 审核端 | `audit` / B | 面向审核员的审核工作台 | — | 状态流主责：李子研 |
| C 后台管理端 | `admin` / C | 面向超级管理员的后台管理与统计 | — | 主责：欧阳昊天 |
| RBAC | `RBAC` | 基于角色的访问控制，三端权限由角色枚举驱动 | 全局 | 单工程、前后端分离 |

> **待确认**：主流程描述中出现过「管理员身份核验」，而角色枚举是「学生 / 审核员 / 超级管理员」。本表按角色枚举执行——**身份核验由审核员在 B 审核端完成**；若契约 v0 另有定义，以契约为准并回来改本行。

## 2. 业务对象（实体）

| 中文名 | 英文/表名（建议） | 定义 | 关键属性 |
|---|---|---|---|
| 用户 | `user` | 系统注册账号，含三类角色 | 学号、姓名、角色、状态 |
| 物品 | `item` | 一条拾获/招领登记所对应的实物台账记录，是状态流转的主体 | 分类、地点、时间、特征描述、图片、状态 |
| 招领登记 | 归 `item` | 拾获人发布的「我捡到了什么」信息 | 拾获时间、拾获地点、保管点 |
| 失物登记 | 归 `item` | 失主发布的「我丢了什么」信息 | 遗失时间、遗失地点、特征描述 |
| 认领申请 | `claim` | 失主对某件物品提出认领、并接受身份核验与审核的单据 | 申请人、关联物品、核验材料、审核结果 |
| 审核记录 | `audit_record` | 审核员对认领申请的一次通过/驳回操作及留痕 | 审核人、结论、意见、时间 |
| 分类字典 | `category` | 物品类别（证件、电子设备、钥匙、书本、衣物、其他） | 分类名、排序、启用 |
| 地点字典 | `location` | 校园地点与保管点 | 地点名、所属区域 |
| 公告 | `notice` | 后台发布的公示/通知 | 标题、内容、有效期 |
| 操作日志 | `operation_log` | 关键操作留痕，供争议追溯与统计 | 操作人、动作、对象、时间 |
| 归还记录 | 建议 `return_record` | 线下归还确认的凭证记录 | 领取人、核验人、归还时间 |

> **待确认**：`return_record` 是否单设表，由契约 v0 的表结构决定；本表不预设字段。表名以契约列出的 `user / item / claim / audit_record / category / location / notice / operation_log` 为基线（≥ 8 张）。

## 3. 业务动作

| 中文名 | 定义 | 执行者 | 对应主流程环节 |
|---|---|---|---|
| 发布登记 | 拾获人或失主录入物品信息并提交（含图片） | 学生 | 发布登记 |
| 搜索浏览 | 按分类 / 地点 / 时间筛选并查看物品详情 | 学生 | 搜索浏览 |
| 提交认领申请 | 失主针对某件物品发起认领，附身份与特征说明 | 学生 | 提交认领申请 |
| 身份核验 | 核对申请人身份与物品特征，判断是否本人 | 审核员 | 身份核验 |
| 审核 | 对认领申请作出通过或驳回结论并留痕 | 审核员 | 审核通过/驳回 |
| 驳回 | 审核不通过，物品回到「待认领」 | 审核员 | 审核通过/驳回 |
| 线下归还确认 | 双方当面交接后，在 B 端确认完成并生成归还记录 | 审核员 | 线下归还确认 |
| 归档 | 物品流程结束后转入历史台账，不再参与搜索 | 系统 / 审核员 | 物品归档 |
| 撤销 | 申请人主动撤回尚未审核的认领申请 | 学生 | 建议扩展流，待契约确认 |
| 争议处理 | 多人认领或冒领疑议时的复核与留痕 | 审核员 | B 审核端 |
| 操作留痕 | 关键动作写入 `operation_log` | 系统 | 全程 |

## 4. 状态枚举

### 4.1 物品状态（契约基线，不得自行增删）

| 中文名 | 英文值（待确认） | 含义 | 允许的下一状态 |
|---|---|---|---|
| 待认领 | `PENDING` | 已发布登记，可搜索、可被申请 | 审核中、已归档 |
| 审核中 | `REVIEWING` | 存在待审核的认领申请 | 待认领（驳回）、已归还（通过后交接） |
| 已归还 | `RETURNED` | 线下交接确认完成 | 已归档 |
| 已归档 | `ARCHIVED` | 流程终结，进入历史台账 | 终态 |

> **驳回规则**：审核驳回 → 物品状态回到「待认领」，不做单独状态。

### 4.2 认领申请状态（v0 建议，待契约确认）

| 中文名 | 含义 |
|---|---|
| 待审核 | 已提交，等待身份核验与审核 |
| 核验中 | 审核员正在核对身份与物品特征 |
| 已通过 | 审核通过，等待线下归还 |
| 已驳回 | 审核不通过，附驳回意见 |
| 已撤销 | 申请人主动撤回 |
| 已完成 | 归还确认后闭环 |

## 5. 数据与字段通用口径

| 术语 | 约定 |
|---|---|
| 学号 | 学生身份唯一标识，登录与身份核验依据 |
| 特征描述 | 失主证明归属的关键信息（颜色、品牌、刻字、内含物等），**公开列表页不展示完整特征**，仅审核端可见，防冒领 |
| 保管点 | 实物存放位置，属地点字典 |
| 公示期 | 物品可认领的时间窗口，超期触发归档；具体天数待契约/需求确认 |
| 图片 | 登记时上传的物品照片，仅作展示，不作为唯一核验依据 |
| 留痕 | 审核、驳回、归还、归档等关键动作必须记入操作日志 |
| 操作人 / 操作时间 | 所有留痕记录的必备字段 |

## 6. 技术与工程术语

| 术语 | 定义 |
|---|---|
| 三端 | A 学生端、B 审核端、C 后台管理端，单工程内按 RBAC 区分 |
| 单工程 | 一套前后端代码仓库支撑三端，不拆三个独立系统 |
| 前后端分离 | Vue3 前端 + Spring Boot 后端，通过 REST 接口交互 |
| 接口契约 v0 | 李子研产出 `api-contract-v0.md`，全组 AI 提示词的公共前缀、5 份材料的唯一依据 |
| 需求追踪矩阵 | 需求编号 ↔ 设计 ↔ 接口 ↔ 测试用例 ↔ 演示步骤的对应关系，批次 2 交叉材料用 |
| 交叉材料 | 对接日产出的 5 份对照表（需求—设计、接口—代码、测试用例、需求—演示、讲稿题库） |

| Mermaid | 本组统一用的文本绘图语法，图以代码块形式嵌在 Markdown 中 |
