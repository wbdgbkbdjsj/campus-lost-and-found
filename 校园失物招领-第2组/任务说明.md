## 一、这份清单在讲什么

一句话：**先各自把文件做出来，再坐到一起对齐合并，不许互相等。**

整个课程设计被切成 4 个批次，共 31 条任务、6 份最终交付物。核心逻辑是「批次 0 的活完全不依赖任何人，5 个人今天同时开工」，对接日只做「对齐 + 合并 + 补交叉」，不从零写。Git 相关（建仓库、提交规范、commit 粒度、版本库截图）**全部暂缓**，等代码能跑、材料齐了再补，别占前两天时间。

### 三条原则

| # | 原则 | 含义 |
|---|---|---|
| 1 | 谁也不等谁 | 批次 0 全部独立开工，不用等接口契约 |
| 2 | 先出东西再对接 | 每人先交一个看得见的文件，对接日只做对齐 |
| 3 | Git 暂缓 | 仓库、提交规范、截图一律往后放 |

### 四批次节奏

| 批次 | 时机 | 干什么 |
|---|---|---|
| 批次 0 | **现在，今天完成** | 5 人各自出独立文件，不等契约 |
| 批次 1 | 契约 v0 到手后 | 各自往下做：补全文档、写代码、细化演示 |
| 批次 2 | 对接日 | 术语对齐、5 份交叉材料、全流程彩排、通读自己主责文档 |
| 批次 3 | 提交前 | 清点命名、终审、打包、彩排主持、1 分钟讲稿 |
