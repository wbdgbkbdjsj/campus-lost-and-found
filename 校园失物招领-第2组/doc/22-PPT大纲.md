## 一、一条主线，三句话

**主线**：一个学生捡到卡包 → 发招领 → 失主搜索到 → 提交认领申请 → 审核员核验身份 → 当面归还 → 归档。系统把这条链路做成有状态、有凭证、可追溯的闭环。

三句话（每页标题只服务其中一句）：

1. **问题真实**：校园失物招领现在靠群消息和宿管阿姨，信息沉底、认领靠嘴说、丢了没法查。
2. **方案闭环**：三端分工 + 状态机 + 凭证核验，把"谁捡的、谁认的、谁批的"全部留痕。
3. **做得出来**：Vue3 + Spring Boot + MySQL 三端跑通，16 页讲完，现场演示 7 步。

> 不讲"我们用了什么先进技术"，讲"我们把一件小事做闭环了"。课程设计答辩最忌讳堆技术名词。

## 三、逐页详案

### 第 1 页 · 封面

- **版面**：L1。左侧 4.6 英寸深靛蓝色块压边，右侧白底放标题。
- **文字**：主标题 `校园失物招领与认领审核系统`；副标题 `—— 从"捡到发群"到"核验归还"的闭环设计`；下方一行 `软件工程课程设计 · 第 2 组`；底部 `组长：阴亮　成员：李子研 · 金道轩 · 邓昌兴 · 欧阳昊天`　`2026 年 11 月`。
- **讲词**（15 秒）："老师好，我们是第 2 组，题目是校园失物招领与认领审核系统。下面用十分钟讲四件事：为什么做、怎么做、跑一遍、以及我们没做好的地方。"

### 第 2 页 · 今天讲四件事

- **版面**：L2。左侧竖排四个序号 + 章节名，右侧对应一句"这页要回答的问题"。
- **文字**：`01 问题`（为什么现有的方式不够用）/ `02 方案`（三端、状态机、审核规则）/ `03 演示`（现场走七步）/ `04 复盘`（测试、分工、不足）。
- **讲词**："先看问题，再看方案，然后现场跑一遍，最后交代我们哪里没做好。"

### 第 3 页 · 丢一把伞，为什么要建一个系统

- **版面**：L5 三栏卡片，每栏一个断点：图标 + 4 字小标题 + 两行说明。
- **卡片 1 · 信息沉底**：招领消息发在几百人的群里，两小时就被刷走，失主根本刷不到；宿管桌上的失物堆到期末没人认。
- **卡片 2 · 认领靠嘴说**：谁说"这是我的"就是谁的。颜色、划痕、夹层里的小票，全靠当面口述，遇到两个人同时来认领就僵住。
- **卡片 3 · 事后无账**：东西给出去了，没记录谁领的、谁批的；真丢了贵重物品，查不出过程。
- **底部结论条**：`缺的不是一个群，是一条有状态、有凭证、可追溯的链路。`
- **讲词**（40 秒）："这三件事我们组五个人都遇到过。第一，信息沉底……第二，认领靠嘴说……第三，给出去就没账了。所以我们不是要做一个更好用的群，是要把这条链路做成有状态的。"
- **素材要求**：**本页不写百分比、不写"调研显示"。** 若要做数据页，须由金道轩在 11-05 前补一次 ≥30 份的小样本问卷，并把样本量写在页脚；没做就不写数字，用场景说话。

### 第 4 页 · 我们做什么，不做什么

- **版面**：L4 左右对照，左"做"（青绿勾），右"不做"（灰色叉）。
- **做**：发布招领信息（图文 + 类别 + 地点 + 时间）；按关键词/类别/地点检索；提交认领申请并上传凭证；审核员核验、通过或驳回；归还登记与归档；全流程操作留痕。
- **不做**（并写清理由）：不做即时聊天（不是本课题范围，微信群更合适）；不做智能图像识别匹配（3 天做不出可用精度，改为类别 + 关键词检索）；不做跨校多租户（单校部署，RBAC 够用）；不做移动原生 App（响应式 Web 即可演示）。
- **底部结论条**：`范围收敛到一条闭环：发布 → 检索 → 申请 → 核验 → 归还 → 归档。`
- **讲词**（30 秒）："我们把范围收得很窄。聊天不做，图像识别不做——三天做不出能用的精度，硬做就是演示时翻车。只做这条闭环，但要做透。"

### 第 5 页 · 三类人，三个端

- **版面**：L5 三栏，每栏：端名（A/B/C）+ 角色 + 3 条核心动作 + 一句"他最怕什么"。
- **A 学生端**：发布招领、检索认领、查看进度。最怕——发了没人看，认了没回音。
- **B 审核端**：核验身份、通过/驳回、登记归还。最怕——两个人同时来认，判错要担责。
- **C 后台端**：用户与角色、类别字典、公告、统计与操作日志。最怕——出了事查不到是谁改的。
- **讲词**（30 秒）："三类人怕的东西不一样，所以三端的信息密度也不一样。学生端要快，审核端要证据，后台端要留痕。"

### 第 6 页 · 一套代码，三个入口

- **版面**：L6 全幅架构图（三层：浏览器/前端 → 接口层 → 数据层），右侧竖排一行技术标签。
- **图内容**：Vue3 + Element Plus 三端（A/B/C，同一工程按路由与角色分流）→ Spring Boot（Controller / Service / Mapper，JWT + RBAC 拦截器）→ MySQL 8（8 张表）+ 本地文件存储（凭证图片）。
- **三个标注**（图上直接标，不另起文字块）：`① 三端共用一套 REST 接口，靠角色收窄返回字段`；`② 状态流转只在 Service 层改，Controller 不许直接写状态`；`③ 凭证文件走静态资源映射，不塞进数据库`。
- **讲词**（40 秒）："一套后端、一套接口，三个前端入口按角色分流。两个纪律：状态只在 Service 层改，图片不进数据库。这两条是我们返工最少的原因。"

### 第 7 页 · 一条申请单的八种状态

- **版面**：L6 全幅状态图。主链四节点横排，下方一条待补充分支，右侧终态区。
- **状态链**（严格按契约 §4.1 的 8 个状态码，不另起中文别名）：
`SUBMITTED 待审核 →（接单）UNDER_REVIEW 审核中 →（通过）APPROVED 待领取 →（交接）COMPLETED 已完成`；
旁支 `UNDER_REVIEW →（退回补充）PENDING_INFO 待补充 →（补交）UNDER_REVIEW`；
终态区 `REJECTED 已驳回 / CANCELLED 已撤销 / EXPIRED 已失效`。
- **批注三条**：`状态只由事件驱动，不能直接改字段`；`每次迁移必写 review_record：谁、什么动作、从哪到哪`；`非法迁移一律拒绝，返回 40001，状态不动`。
- **讲词**（40 秒）："八个状态，一条回退路径，三个终态。为什么要状态机？因为'这一单现在能不能动'如果没有唯一答案，前后端一定会吵。状态机就是那个唯一答案。"
- **v1.1 修正说明**：初稿写的是"待认领 / 核验中 / 待归还 / 已归还 / 已归档"七个业务口语状态，与契约 v0 的 8 个状态码对不上。这是**必须改的**——答辩时评委拿《接口文档》一对就发现两套说法。现已统一为「状态码 + 中文名」并列，页面文字与 `api-contract-v0.md` §4.1 完全一致。

### 第 8 页 · 功能地图：谁在哪一端做什么

- **版面**：L7 矩阵表。行=模块（发布 / 检索 / 认领 / 审核 / 归还 / 归档 / 系统管理），列=A 学生端 / B 审核端 / C 后台端 / 接口组。
- **格内**：打点表示该端有该功能，空白表示没有；接口组写接口前缀，如 `/api/items`、`/api/claims`、`/api/audit`。
- **底部结论条**：`22 个功能点，每个点都能指到一个接口、一个页面、一条用例。`
- **讲词**（30 秒）："这张表是我们对接时的唯一凭据。一个功能点如果指不到接口，说明它没设计；指到接口但没有页面，说明它没实现。"

### 第 9 页 · 7 张表撑起整条链路

- **版面**：L6 全幅 ER 简图，只画方框和主外键连线，**不写字段**（字段在文档里，页面上写不下也没人看）。
- **7 张表**（契约 §2）：`user` 用户、`found_item` 拾获物品、`lost_item` 失物启事、`claim` 认领申请、`review_record` 审核流水、`notification` 通知、`audit_log` 操作日志。
- **三处高亮**：`claim` 是链路中枢（同时挂物品、申请人、审核员）；`review_record` 只增不改；`lost_item` 与 `found_item` **之间不建外键**，靠类别 + 关键词匹配（虚线表示），这是有意的取舍。
- **讲词**（35 秒）："七张表，认领申请是枢纽。注意审核流水只增不改——这是能追溯的前提。另外失物启事和拾获物品之间没建外键，靠类别和关键词匹配，这是取舍，不是遗漏。"
- **v1.1 修正说明**：初稿写"8 张表（用户 / 角色 / 物品类别 / 招领信息 / 物品图片 / 认领申请 / 认领凭证 / 审核与归还记录）"，与契约对不上：角色已合并为 `user.role` 字段，物品图片与认领凭证都是字段而非独立表，且缺了通知与日志两张。已按契约 §2 改为 7 张表。

### 第 10 页 · 怎么防止冒领

- **版面**：L4 左右对照。左：三道关；右：一次真实驳回的截图/示意。
- **左（三关）**：
  1. **必填特征**：认领申请必须填"只有失主知道的细节"（内衬颜色、划痕位置、夹层物品），少于 20 字不予提交。
  2. **凭证上传**：购买记录、序列号、同期照片，至少一项；凭证仅审核员可见。
  3. **双人复核**：贵重物品（金额 \> 500 元）需两名审核员先后确认，任一人驳回即退回。
- **右（驳回示意）**：一张申请卡片，标注驳回原因 `特征描述与实物不符：描述为"黑色"，实物为深棕色`。
- **底部结论条**：`判错的成本 > 判慢的成本，所以宁可多一道核验。`
- **讲词**（50 秒）："这是整个系统最值钱的一页。三关：必须写只有失主知道的细节、必须上传凭证、贵重物品双人复核。驳回也要写理由，理由进日志，下次同一个人再来认领，审核员能看到历史。"

### 第 11 页 · 权限不是开关，是数据边界

- **版面**：L4 左右。左：RBAC 三角（用户—角色—权限）；右：一张"同一接口、不同角色返回不同字段"的对照表。
- **表**：`GET /api/items/{id}` —— 未登录：公开字段；学生：公开 + 自己的申请状态；审核员：全部 + 申请人信息 + 凭证；管理员：全部 + 操作日志。
- **批注**：`越权校验在拦截器统一做，不在每个 Controller 里复制`。
- **讲词**（30 秒）："权限不是'能不能进这个页面'，是'同一条数据，你能看到几个字段'。这个我们是在接口层收窄的，不是在页面上藏按钮。"

### 第 12 页 · 现场走一遍：从捡到到归还

- **版面**：L6 全幅。主区放 7 张手机/浏览器截图，横向排成一条时间轴，每张下方一行小字（操作 + 结果）。
- **七步**：① 学生发布招领（含 2 张图）② 失主按"卡包 + 图书馆"检索到 ③ 提交认领申请并填特征、传凭证 ④ 审核员看到待办，打开核验页 ⑤ 通过，状态转"待归还" ⑥ 当面交接，扫领取码登记归还 ⑦ 归档，两端都收到结果，后台留审计日志。
- **兜底**：**预录 1 分 40 秒视频**，现场网络或数据库出问题时直接播，不在台上 debug。
- **讲词**（100 秒）：边走边讲，每步一句话，不解释界面细节。"第一步，发布……第三步，注意这里必须填特征才能提交……第五步，通过之后状态自动转待归还，学生端立刻能看到……"
- **纪律**：演示只走 happy path，异常分支留给答辩口头回答（题库里有）。

### 第 13 页 · 测试：把需求逐条打勾

- **版面**：L7 矩阵表。行=需求条目分组，列=用例数 / 已执行 / 通过 / 未通过 / 对应缺陷。
- **指标**：用例 **74 条**（P0 30 / P1 39 / P2 5）；接口覆盖 24/24；claim 状态覆盖 8/8；合法迁移 12/12；非法迁移抽样 13 条。通过率在 R1/R2 执行后填真值，不预估。
- **一行结论**：`每条需求至少一条用例；没通过的用例都有缺陷编号，不写"已知问题"。`
- **讲词**（35 秒）："测试用例是按需求说明书逐条写的，不是按页面写的。所以这张表能反过来说明：需求里写的每一条，都有人验过。"

### 第 14 页 · 3 天怎么分工的

- **版面**：L7 矩阵表 + 右侧一条时间轴。
- **表**：五行五人，列=批次 0（出东西）/ 批次 1（往下做）/ 批次 2（对接）/ 批次 3（收尾），格内写交付物名。
- **时间轴**：11-04 并行出件 → 11-05 契约到手各自开工 → 11-06 对齐合并彩排 → 11-07 上午终审提交。
- **一句批注**：`契约（数据字典 + 接口）先出，其余四人的活全部挂在它后面，所以它由一个人独占，不加活。`
- **讲词**（30 秒）："我们没有按模块横切，是按'先出东西再对接'竖切。每个人先交一个能打开的文件，对接日只做对齐，不从零开始写。"

### 第 15 页 · 没做好的三件事

- **版面**：L5 三栏，每栏一句"问题 + 影响 + 下一步"。
- **① 图像匹配没做**：只做了类别 + 关键词检索，捡到和丢失的描述用词不一致时召回低。下一步：接 CLIP 做图文相似度，或做同义词表。
- **② 通知只有站内信**：没有短信/微信推送，认领结果靠用户自己回来看。下一步：接模板消息。
- **③ 审核时效无 SLA**：待办超过 24 小时没有提醒机制，真实场景会积压。下一步：加超时提醒与升级规则。
- **讲词**（20 秒）："这三件我们知道该做但没做，不是忘了，是三天做不完。"
- **原则**：主动交代的范围要可控——只说实现层面的取舍，不质疑需求与设计本身。

### 第 16 页 · 请提问

- **版面**：L8。左：`感谢聆听`；右：`Q & A`；底部一行 `源码 / 文档 / 演示视频 已随提交包提供`。
- **讲词**（10 秒）："以上是第 2 组的汇报，请老师提问。"

### 4.5 页眉页脚（母版里一次设好）

- 页脚左：`软件工程课程设计 · 第 2 组`（10pt，40% 灰）

- 不设页眉，不在页脚放校徽

### 4.6 图表与截图规范

- 架构图、状态图、ER 图**统一用 PowerPoint 形状画**，不用截图贴图（放大糊、改不动）。
- 形状统一：圆角矩形 0.05"、线宽 1pt、连接线 1pt 青绿、箭头为实心三角。
- 截图统一 1440×900 或 390×844（手机端），加 1pt `#D5DCE5` 边框 + 2% 阴影；截图里**不许出现真实姓名、手机号、学号**。
- 表格不用 PPT 默认样式，手动设：表头深靛蓝底白字、正文行高 0.4"、去掉竖线（只留横线，同文档三线表口径）。

### 4.7 动画与切换

- 只用"淡出"，时长 0.3s，逐条出现（要点按段落级）。
- 不用飞入、旋转、缩放、平滑切换；不用音效。
- 演示页（第 12 页）不做动画，直接整页呈现。

### 4.8 母版落地步骤（20 分钟）

**已经做成了文件**：`答辩PPT-母版.pptx` 里按 L1–L8 做好 8 页样板（封面 / 路线图 / 章节页 / 三栏 / 左右对照 / 全幅图 / 矩阵表 / 结尾），配色、字号、页脚页码全部到位。做法是**复制整页再改字**，不要从空白页重搭。若要自建，按下面六步：

1. 新建空白演示文稿 → 设计 → 幻灯片大小 → 自定义 13.333×7.5。
2. 视图 → 幻灯片母版 → 保留"标题幻灯片"和"仅标题"两个版式，其余删掉。
3. 在母版上放页脚左右两块文本框（占位符式），设 10pt 灰字。
4. 按 L1–L8 复制出 8 个版式，只改占位符位置，不塞具体内容。
5. 主题字体设"微软雅黑"（中文）+ "Segoe UI"（西文），主题颜色按 4.2 建一组。
6. 关闭母版视图 → 另存为 `第2组-答辩PPT-模板.potx`，全组只用这一个文件起新页。
