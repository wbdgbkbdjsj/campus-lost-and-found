## 1 为什么这么做（先看，别一上来就 Vite）

| 判断 | 理由 |
|---|---|
| **用 Vue 3 global build + 本地 vendor 文件，不搞 Vite 构建链** | 答辩机不一定有 Node；本机虽有 Node 22 / npm 10，但打包、路径、部署任何一环出问题，现场就白给。Vue 3 本地文件既符合文档「Vue3」口径，又零构建、断网可跑 |
| **前端由 FastAPI 同源托管，不开 CORS** | 浏览器从 `file://` 或 `:5173` 调 `:8000` 会被跨域拦死。同源挂在 `http://127.0.0.1:8000/` 下，一条 `uvicorn` 命令全起来，`/docs` 也还在 |
| **不做 C 端页面** | 契约 §3.4 写明 C 端 #25–30 是**欧阳昊天的实现范围，原型未含**。你只做「后台端（原型未实现）」的占位导航，**严禁编假数据**，别抢他的活、也别给自己埋雷 |

> 如果你确实想留 Vite 工程：单独放 `05_源码/frontend-vite/`，`npm run build` 产物输出到 `web/dist/`，**只作为源码工程化证据，不许当演示依赖**。演示永远走 `web/index.html` 那条零构建链路。

## 3 后端只改这 3 处（可直接复制粘贴）

`main.py` 顶部 import 区追加：

```python
import os
from fastapi.staticfiles import StaticFiles
from fastapi.responses import FileResponse
```

`main.py` **文件最末尾**（所有 `@app` 路由之后，务必放最后）追加：

```python
# ---------------- 前端静态托管（同源，零 CORS） ----------------
WEB_DIR = os.path.join(os.path.dirname(__file__), "web")
app.mount("/static", StaticFiles(directory=WEB_DIR), name="static")


@app.get("/", include_in_schema=False)
def web_index():
    return FileResponse(os.path.join(WEB_DIR, "index.html"))
```

前端里资源一律写 `/static/app.js`、`/static/style.css`、`/static/vendor/vue.global.prod.js`。

> 为什么 `mount("/static")` 而不是 `mount("/")`：后者会把未知的 `/docs` 吞掉。挂 `/static` + 单独 `@app.get("/")`，互不干扰。
>
> ⚠️ **顺序坑（会直接让后端起不来）**：`StaticFiles(directory=...)` 在 import 时就会检查目录，**必须先建好 `05_源码/web/` 目录（哪怕先放一个空 `index.html`）再加这段挂载**，否则 `import main` 抛 `RuntimeError`，连 `smoke_test.py` 都跑不了。建议先把第 2 节那几个前端文件落地，最后再加后端 3 行。
>
> ⚠️ **只改 `05_源码/main.py` 这一份**（交付版），别在 `02-李子研/server/` 里另改一份，否则两份代码分叉，我打包时不知道该交哪个。
>
> 改完**必须**跑一次 `python smoke_test.py`，仍要 24/24 全绿才算没碰坏后端。

## 4 页面 ↔ 演示步 ↔ 接口对照表（照着做就行）

| # | 页面 / 组件 | 演示步 | 调的接口 | 要点 |
|---|---|---|---|---|
| 1 | 登录页 | 1、8 | `POST /api/v1/auth/login`、`GET /auth/me` | 四个种子账号；按 `data.user.role` 切三端菜单 |
| 2 | A · 拾获登记 | 2 | `GET /dict/categories`、`/dict/locations`、`POST /found-items` | 分类/地点下拉取字典，别写死 |
| 3 | A · 招领列表 / 搜索 | 4 | `GET /found-items?keyword=&page=&size=` | 关键词检索，列表显状态码 + 中文名 |
| 4 | A · 物品详情 | 5 | `GET /found-items/{id}` | 展示 `status`、保管点 |
| 5 | A · 认领申请 | 6 | `POST /claims` | `proof` 必填，前端做非空校验（防冒领第一关） |
| 6 | A · 我的认领单 | 7、14 | `GET /claims`、`GET /claims/{id}` | 用返回的 `records` 回放流水 |
| 7 | B · 审核队列 | 8 | `GET /review/queue` | 按提交时间升序 |
| 8 | B · 认领单详情 | 9、10、11 | `POST /review/claims/{id}/accept`、`/approve`、`/reject`、`/request-info` | **按钮显隐直接用后端返回的 `allowed_events`**，不要在前端硬编码状态判断 |
| 9 | B · 身份核验 | 12 | `POST /review/claims/{id}/verify` | 录入到场人 `student_no` + `name`；返回 `verified`，**页面提示「状态不变，已写 VERIFY 流水」** |
| 10 | B · 交接确认 | 13 | `POST /review/claims/{id}/handover` | **未核验时按钮要能点，把后端 `40003` 用红色提示原样显示出来** —— 现场演示 I7 约束比直接禁用更有说服力 |
| 11 | B/A · 流水与通知 | 15 | `GET /claims/{id}`（`records`）、`GET /notifications` | 能看到 `APPROVED --VERIFY--> APPROVED` 自环 |
| 12 | C · 占位页 | — | 无 | 只写「后台管理端：契约 #25–30 已设计，原型未实现」，**不放假数据** |

**三端菜单按角色切**：`student` → A 学生端；`reviewer` → B 审核端；`super_admin` → C 占位页。**角色值只有这三个，`admin` 已废弃。**

**顺序不能画反**：`提交 → 接单 → 审核通过(#20) → 身份核验(#19，APPROVED 自环、不改状态) → 交接(#23，I7 前置)`。UI 上核验入口出现在「通过」之后、「交接」之前。
