| 目录 | 技术栈 | 状态 | 在评分里的作用 |

## 2 ★ 前端唯一口径裁决（组长 2026-11-05 拍板）

原先两套前端并存，容易让评审看到互相矛盾的界面。**现定死**：

| 用途 | 用哪套 | 说明 |
|---|---|---|
| **现场演示 / 演示视频 / 软件界面原型 / 作业四「系统可运行」** | ✅ **`lost-found-prototype/`**（FastAPI + 零构建单页） | 唯一真实跑通主链、有 6 张真界面截图、15/15 端到端、后端 24/24 全绿的那套 |
| **正式技术方案骨架 / 代码规模 / 体系结构与构件设计 / 用户界面模型取材** | `lost-found-web/` + `lost-found-server/` | 作为「正式栈工程结构」展示，**不作为演示界面**，也不再投入时间联调 |
| 断网保底 | `lost-found-prototype/` 自带 `/docs` Swagger UI + `smoke_test.py` | 前端出问题时现场直接跑 24 项，核心流程照样讲得清 |

**因此**：不再把邓的 Vue 工程接到 FastAPI 做演示联调（任务 02 v2 的 8 处 v0 假设改造**停止执行**，见 `00_任务总览/李子研-任务02…md` v3 裁决）。理由：指导书看的是「系统完成度 / 演示 / 需求实现匹配度」，把已经跑通的一套讲透，比同时摆两套半成品强；且临近提交，联调风险远大于收益。

**答辩统一答法**（替换旧版「现场演示是邓的 Vue 界面 + FastAPI 后端」）：
> 现场演示用的是 `lost-found-prototype/`：FastAPI 业务后端挂载零构建 Vue3 单页，24 项冒烟两次复现全绿、浏览器端到端 15/15 通过。Vue3 工程化前端与 Spring Boot 后端是正式技术方案骨架（可构建 / 可编译），按契约一一对应、可平移，本轮不宣称其业务层已实现。

## 3 怎么跑（演示主口径）

```bash
cd src/lost-found-prototype
python -m pip install -r requirements.txt
python smoke_test.py                 # 期望：通过 24 项，失败 0 项
uvicorn main:app --reload            # 浏览器打开 http://127.0.0.1:8000/
```

`main.py` 比纯 API 版多了 3 行 import 与文件末尾的静态挂载段，指向同目录 `web/`；四个业务模块（`models.py` / `service.py` / `state_machine.py` / `smoke_test.py`）与 `05_源码/` 逐字一致。零构建单页无 CDN 依赖，**可离线演示**。
