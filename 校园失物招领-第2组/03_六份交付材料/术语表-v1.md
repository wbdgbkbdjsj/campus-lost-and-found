## 0. 使用约定

1. **一词一义**：一个概念只保留一个中文名，其余叫法进第 8 节禁用表。
2. **中文名优先**：正文、界面、PPT 用中文名；代码、数据库、接口用英文代码名（代码变量与口头简称不受禁用表约束）。
3. **三角色与代码名**：只用 `student` / `reviewer` / `super_admin`；表/字段 `snake_case`，接口 `/api/v1` 前缀，状态枚举大写下划线。

> **编号空间、文档格式、图题表题、口径变更流程、版本归档、提交命名统一见《全组约定与编号总则-v1.md》**，本表不再重复维护；冲突时按该总则 §1 的优先级判定。现行与否看文档头部「状态」栏，不看文件名里的 v0/v1。

## 1. 角色与端

| 中文名 | 英文代码名 | 定义 | 归属端 |
|---|---|---|---|
| 学生 | `student` | 在校注册用户，发布登记、搜索物品、提交认领申请 | A 学生端 |
| 拾获人 | `finder` | 拾到物品并发布招领登记的学生，是「学生」的**场景称呼**，不新增角色、不单设数据库角色 | A 学生端 |
| 失主 | `owner` | 遗失物品、发起认领申请的学生，同为场景称呼 | A 学生端 |
| 审核员 | `reviewer` | 接单、身份核验、审核通过/驳回、退补、交接、争议处理 | B 审核端 |
| 超级管理员 | `super_admin` | 用户管理、分类/地点字典、统计看板、操作日志、Excel 导出 | C 后台管理端 |
| A 学生端 | `portal` / A | 面向学生的前台 | — |
| B 审核端 | `audit` / B | 面向审核员的审核工作台 | — |
| C 后台管理端 | `console` / C | 面向超级管理员的后台管理与统计 | — |

> ⚠️ **`admin` 代号在 v1 中废弃**。v0 中 `admin`=审核员，与 v0 本表中 `admin`=超级管理员撞车；契约 v1 已统一为三角色，全组不得再出现 `admin` 作为角色值。

## 2. 业务对象（实体，共 9 张表）

| 中文名 | 英文表名 | 说明 |
|---|---|---|
| 用户 | `user` | 注册账号，含 `student` / `reviewer` / `super_admin` 三类角色与 `ACTIVE`/`DISABLED` 状态 |
| 分类字典 | `category` | 物品类别，C 端维护、A/B 端下拉复用 |
| 地点字典 | `location` | 校园地点与保管点 |
| 失物启事 | `lost_item` | 失主发布的「我丢了什么」，状态 `OPEN`/`MATCHED`/`CLOSED` |
| 拾获物品 | `found_item` | 拾获人登记的「我捡到了什么」，状态流转主体 |
| 认领申请 | `claim` | 核心单据，携带审核状态机 |
| 审核流水 | `review_record` | 每次状态迁移写一条，含 `VERIFY` 核验流水，可回放历史 |
| 通知 | `notification` | 站内通知（审核结果、退补、超期） |
| 操作日志 | `audit_log` | 关键动作留痕，C 端日志查询数据源 |

> 英文表名采用契约 v1 的**双表设计**（`lost_item` / `found_item` 分开），中文「物品」作为两者统称继续在正文使用。
> **不单设** `return_record` 表：归还落在 `claim.status=COMPLETED` + `found_item.status=CLAIMED` + `review_record` 流水。
> **不设** `notice` 表：公告（FR-15）为 P2 遗留需求，v1 契约未提供接口，本版不实现。
> v0 基线中的 `item` / `audit_record` / `operation_log` / `notice` 一律作废。

## 3. 业务动作（按契约 v1 顺序）

| 中文名 | 定义 | 执行者 | 接口 # |
|---|---|---|---|
| 发布登记 | 录入拾获/遗失信息并提交 | 学生 | 9 / 11 |
| 搜索浏览 | 按分类 / 地点 / 时间筛选 | 学生 | 7 / 10 |
| 提交认领申请 | 附凭证特征发起认领，`proof` 必填 | 学生 | 12 |
| 接单 | 审核员锁定该单，`reviewer_id` 绑定 | 审核员 | 18 |
| 审核 | 通过 / 驳回 / 退回补充，附意见 | 审核员 | 20 / 21 / 22 |
| **身份核验** | 到场后核对学号姓名，**不改状态**，写 `VERIFY` 流水 | 审核员 | **19** |
| 线下归还确认 | 交接完成后确认闭环（**I7：须先有 VERIFY 通过流水**） | 审核员 | 23 |
| 超时失效 | 定时任务扫描 `deadline`，超期置 `EXPIRED` | 系统 | 24 |
| 撤销 | 申请人撤回非终态单据 | 学生 | 16 |
| 补充材料 | `PENDING_INFO` 状态下补凭证 | 学生 | 15 |
| 操作留痕 | 关键动作写 `review_record` + `audit_log` | 系统 | 全程 |

> **顺序口径**：提交 → 接单 → 审核通过 → **身份核验** → 交接。身份核验是 `APPROVED` 自环，不是审核前的一步；v0 文档与部分 PPT 页仍写作「核验在审核前」，须按此更正。

## 4. 状态枚举

### 4.1 物品状态（`found_item.status`）

| 英文值 | 中文名 | 说明 |
|---|---|---|
| `REGISTERED` | 已登记 | 可被搜索、可被申请 |
| `CLAIMING` | 认领中 | 提交认领后置入，防止重复申请 |
| `PICKUP_PENDING` | 待领取 | 审核通过，7 天内领取 |
| `CLAIMED` | 已归还 | 交接完成 |
| `CLOSED` | 已归档 | 终态，进入历史台账 |

> 驳回 / 撤销 / 超时均回退 `REGISTERED`，物品重新可被认领。

### 4.2 认领申请状态（`claim.status`，8 态）

| 英文值 | 中文名 | 终态 |
|---|---|---|
| `SUBMITTED` | 待审核 | 否 |
| `UNDER_REVIEW` | 审核中（已接单） | 否 |
| `PENDING_INFO` | 待补充材料 | 否 |
| `APPROVED` | 审核通过·待领取 | 否 |
| `REJECTED` | 已驳回 | 是 |
| `CANCELLED` | 已撤销 | 是 |
| `COMPLETED` | 已完成（已交接） | 是 |
| `EXPIRED` | 已失效（超时） | 是 |

## 5. 数据与字段通用口径

| 术语 | 约定 |
|---|---|
| 学号 | 学生身份唯一标识，登录与身份核验依据 |
| 特征描述 | 证明归属的关键信息（颜色、刻字、内含物等），**公开列表页脱敏**，仅审核端可见 |
| 保管点 | 实物存放位置，来自 `location` 字典 |
| `deadline` | 待补充 / 待领取两态的截止时间，默认 **+7 天**；不再使用「公示期」一词 |
| 图片 | 登记时上传的物品照片，仅作展示，不作为唯一核验依据 |
| 操作留痕 | 审核、驳回、核验、归还等关键动作双写 `review_record` 与 `audit_log` |
| 字段约束 | 契约 v1 §2 全表标注 NN（非空）与 DEF（默认值），实现不得自行增删 |
