## 3 已实现并可验证的功能（24 条路由）

**A 学生端（13 条）**：登录 / 当前用户 / 分类字典 / 地点字典；招领与失物登记的新建、列表、详情；认领申请的新建（凭证必填）、列表、详情、补充材料；我的通知。

**B 审核端（11 条，课题核心）**：审核队列（`SUBMITTED` + 超时 `PENDING_INFO`，按提交时间升序）、接单（锁定 reviewer）、**身份核验（#19，`APPROVED` 自环、不改状态、写 `VERIFY` 流水）**、审核通过、驳回、退回补充、线下归还确认（#23，前置 I7）、撤销、超时批处理、审核历史流水。

**C 后台端**：原型仅实现三角色登录与 `super_admin` 账号；用户管理 / 字典维护 / 公告 / 统计看板 / 日志导出（契约 #25–30）为**设计已定义、代码未实现**，见第 5 节。

**状态机**：认领单 8 态 `SUBMITTED` `UNDER_REVIEW` `PENDING_INFO` `APPROVED` `REJECTED` `CANCELLED` `COMPLETED` `EXPIRED`，12 条合法迁移，4 个终态封闭；物品 5 态 `REGISTERED`→`CLAIMING`→`PICKUP_PENDING`→`CLAIMED`，旁路 `CLOSED`，驳回 / 撤销 / 超期统一回退 `REGISTERED`。

**不变量**：I1 终态封闭 `40001`、I5 驳回/退补意见必填、I6 审核动作限已接单 reviewer 本人 `40002`、**I7 交接前必须存在 VERIFY 通过流水 `40003`**。

## 4 正确流程（答辩要背）

```
提交(#12) → 接单(#18) → 审核通过(#20) → 身份核验(#19，不改状态) → 交接(#23，校验 I7)
```

**审核是线上判断凭证与物品特征是否匹配；核验是到场后核对本人学号姓名，必须线下，时机天然在后。** 把核验做成 `APPROVED` 自环，可以保证未通过的申请不会留下核验流水，同时让交接有可举证的前置。冒烟脚本里有专门一组验证「未核验就交接 → 40003」与「核验后交接 → COMPLETED」。

## 5 双轨技术栈与边界（务必如实讲）

| | 正式方案（文档口径） | 本目录（可运行实体） |
|---|---|---|
| 栈 | Vue3 + Spring Boot 3 + MyBatis-Plus + MySQL 8 + Nginx | FastAPI + SQLAlchemy + SQLite |
| 定位 | 总体设计、部署设计、构件划分的正式方案 | **审核状态流同构原型**：早期验证、冒烟测试、演示保底 |
| 对应关系 | `review-module` / `state-machine` / Controller / 实体 | `service.py` / `state_machine.py` / `main.py` / `models.py`，一一对应 |

* 答辩若被问「说好 Spring Boot 怎么交 Python」：本目录是**同构原型**，用来把最难的状态机与 I7 防冒领规则先跑通并留下 24 项测试证据；正式工程的构件划分、接口契约、状态机迁移表完全一致，可以直接平移，见《总体设计报告》§3/§6 与《设计说明书》附录 A。
* **不要说三端都做完了**：目前可运行的是 B 端审核状态流 + A 端基础接口，C 端后台与前端页面属于设计与 PPT 范围，尚未编码。如实说清楚边界，比被问穿更安全。
