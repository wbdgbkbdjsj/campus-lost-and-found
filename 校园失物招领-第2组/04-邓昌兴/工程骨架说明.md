## 4. 三端在单工程里怎么隔离

### 4.1 隔离靠四层，任意一层单独都不够

| 层 | 机制 | 位置 |
|---|---|---|
| 1. 路由前缀 | `/student`、`/audit`、`/admin` | `router/modules/*.ts` |
| 2. 路由元信息 | `meta.roles: ['STUDENT']` | 同上 |
| 3. 全局守卫 | 未登录去登录页；角色不符跳回本角色首页 | `router/guards.ts` |
| 4. 后端注解 | `@PreAuthorize("hasRole('AUDITOR')")` | 各 Controller |

> **前端守卫只是体验，后端注解才是安全边界。** 答辩如果被问「前端能不能绕过权限」，答案就是这一句。

### 4.2 登录后如何落到正确的端

```
POST /auth/login
  → 返回 { token, user: { role } }
  → authStore 存 localStorage
  → ROLE_HOME[role] 决定跳转：
       STUDENT → /student/home
       AUDITOR → /audit/workbench
       ADMIN   → /admin/dashboard
```

### 4.3 越权访问的表现

- 学生手动输入 `/audit/workbench` → 守卫发现 `role != AUDITOR` → 跳回 `/student/home`。
- 用学生 Token 直接调审核接口 → 后端 `@PreAuthorize` → 403 + `{code:403}`。

## 5. 一次请求的完整链路

```
页面 (views/student/home/index.vue)
  │  调用 pageItems(params)
  ▼
api/item.ts
  │  request.get('/items', { params })
  ▼
utils/request.ts
  │  请求拦截：从 localStorage 取 token → Authorization: Bearer xxx
  ▼
Vite dev server  /api  →  http://localhost:8080/api
  ▼
Spring Security
  │  JwtAuthenticationFilter 解析 Token → LoginUser + ROLE_STUDENT
  │  @PreAuthorize 校验角色
  ▼
Controller → Service → Mapper → MySQL
  ▼
Result<PageResult<ItemVO>>  { code:200, message:"操作成功", data:{...} }
  ▼
axios 响应拦截：code !== 200 弹错误并 reject；否则直接返回 data
  ▼
页面拿到 PageResult，交给 useTable / ProTable 渲染
```

**约定**：页面里**永远拿不到** `code/message` 外壳，只会拿到 `data`；需要提示错误由拦截器统一弹。

## 6. 统一约定（写代码前先看这节）

### 6.1 响应结构

```json
{ "code": 200, "message": "操作成功", "data": { } }
```

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数校验失败 |
| 401 | 未登录 / Token 过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 4000 | 业务失败（如「该物品已被认领」） |
| 500 | 服务器异常 |

### 6.2 分页

- 入参：`current`（从 1 开始）、`size`。
- 出参：`{ records, total, current, size }`。
- 前端统一用 `composables/useTable.ts`。

### 6.3 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 前端组件文件 | PascalCase | `ProTable.vue` |
| 前端页面目录 | kebab-case | `my-items/index.vue` |
| 前端变量/函数 | camelCase | `pageItems` |
| 后端类 | PascalCase | `ItemController` |
| 后端包 | 全小写 | `module.item.controller` |
| 接口路径 | 全小写 + 复数资源 | `/api/items`、`/api/claims` |
| 数据库表/列 | snake_case | `claim_apply`、`create_time` |
| 枚举值 | 全大写下划线 | `PENDING`、`APPROVED` |

### 6.4 时间与文件

- 时间：后端 `LocalDateTime`，JSON `yyyy-MM-dd HH:mm:ss`；前端统一用 `formatDateTime`。
- 图片：后端存 `./uploads`，返回可访问 URL；前端统一走 `api/file.ts` 上传。
