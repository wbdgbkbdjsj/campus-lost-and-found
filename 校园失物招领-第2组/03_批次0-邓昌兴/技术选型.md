## 1. 为什么这么选（只讲三天内成立的理由）

| 决策 | 理由 | 不选另一个的原因 |
|---|---|---|
| Vue3 而非 React | 组内 Vue 基础更好；Element Plus 的表格/表单/弹窗直接对应审核端和后台端 | React + AntD 学习成本、生态写法分散，三个人更难统一 |
| TypeScript 而非 JS | 三个人分端写代码，接口字段靠类型对齐，改错立刻报红 | 纯 JS 省事但「字段对不上」只能在联调时炸 |
| Element Plus 而非 Naive/AntD-Vue | 国内课程设计最常见，AI 生成示例最多，答辩老师也认 | 另外两个的表格封装和文档量都不如它 |
| MyBatis-Plus 而非 JPA | 课程要求写 SQL/表结构，MP 单表零 SQL、复杂查询可控，便于讲「数据访问层」 | JPA 自动建表会掩盖表设计，答辩时讲不清 |
| Spring Security + JWT 而非 Session | 前后端分离、单页应用；Token 放 Header，天然支持三端 | Session 要处理跨域 Cookie，部署更麻烦 |
| 单前端工程三端而非三个工程 | 一份依赖、一份公共组件、一次构建；RBAC 路由天然隔离 | 三个工程三倍安装/构建时间，公共组件要复制三份 |
| 单后端工程分模块而非微服务 | 3 天、单机演示，微服务是纯负担 | 微服务需要注册中心/网关，答辩也讲不完 |
| 本地磁盘存图而非 OSS/MinIO | 演示环境离线可跑，零额外服务 | OSS 要账号和网络；MinIO 多一个进程 |
| 不用 Redis | JWT 无状态，退出登录前端删 Token 即可；本项目无高频缓存需求 | 少一个必须启动的中间件，少一类「环境跑不起来」的故障 |
| 不用 Docker | 机房/演示机直接 `java -jar` + `npm run build` | Docker 在 Windows 学生机上经常卡在虚拟化 |

| vue-tsc | ^2.1.10 | 类型检查（`npm run build` 前置） |

| prettier | ^3.4.1 | 格式化 |

**硬性约定**

- 只用 **组合式 API + `<script setup lang="ts">`**，不写 Options API。
- 所有接口调用集中在 `src/api/`，页面里**不直接写 axios**。
- 所有接口返回统一走 `utils/request.ts`，页面拿到的直接是 `data`。
- 组件文件名用 **PascalCase**（`ProTable.vue`），页面目录用 **kebab-case**（`my-items/index.vue`）。
- 不引入第二套 UI 库，不写内联 `style` 做布局（一律 class + scss）。

## 3. 后端技术清单（版本锁定）

| 依赖 | 版本 | 用途 |
|---|---|---|
| spring-boot-starter-web | 3.2.5 | Web |
| spring-boot-starter-security | 3.2.5 | 认证授权 |
| spring-boot-starter-validation | 3.2.5 | 参数校验 |
| mybatis-plus-spring-boot3-starter | 3.5.7 | ORM |
| mysql-connector-j | Boot 管理（8.3.x） | 驱动 |
| jjwt-api / jjwt-impl / jjwt-jackson | 0.11.5 | JWT |
| knife4j-openapi3-jakarta-spring-boot-starter | 4.5.0 | 接口文档 / 调试 |
| lombok | Boot 管理 | 简化实体 |
| spring-boot-starter-test | 3.2.5 | 测试 |

**硬性约定**

- JDK 17，Maven 单模块工程，**不做多模块**（多模块只增加配置量）。
- 分包按**业务模块**：`module/模块名/{controller,service,mapper,entity,dto,vo}`，不按 `controller/` 全平铺（三人并行不抢文件）。
- 统一返回 `Result<T>`，统一异常 `BusinessException` + `GlobalExceptionHandler`。
- 分页统一 `PageResult<T>`，参数 `current` / `size`。
- 权限用 `@PreAuthorize("hasRole('AUDITOR')")` 方法级注解，不在 Controller 里手写 if。
- 密码 `BCryptPasswordEncoder`，数据库里**不存明文**。
- 时间统一 `LocalDateTime`，JSON 输出 `yyyy-MM-dd HH:mm:ss`。

## 4. 数据库与文件存储

| 项 | 定值 |
|---|---|
| 数据库 | `lost_found` |
| 字符集 | `utf8mb4` / `utf8mb4_general_ci` |
| 表名前缀 | 无前缀，`snake_case`（`item`、`claim_apply`、`audit_record`） |
| 主键 | `bigint` 自增 `id` |
| 公共字段 | `create_time`、`update_time`、`deleted`（逻辑删除 0/1） |
| 图片存储 | 后端 `./uploads/`，访问路径 `/api/files/{文件名}` |
| 上传限制 | 单文件 10MB，单次 20MB，仅 jpg/png/jpeg/webp |

> ⚠️ 具体表结构**不在本文件定**，以李子研《api-contract-v0.md》为准。本文件只定「存哪里、怎么命名」。

## 7. 三天风险与兜底

| 风险 | 兜底方案 |
|---|---|
| 某人前端进度落后 | 页面已按 P0/P1/P2 分级（见《页面清单.md》），先保 P0，P1 直接砍 |
| 联调字段对不上 | 一律以 `api-contract-v0.md` 为准；前端字段集中在 `src/types/`，只改一处 |
| Maven / MySQL 环境跑不起来 | 用 IDEA 内置 Maven；MySQL 用图形客户端启动；仍不行则换组员机器 |
| 图片上传失败影响演示 | 上传失败时允许跳过图片，演示用预置图片 URL |
| 时间不够做图表 | ECharts 只服务后台看板，属 P1，可整页砍掉不影响主流程 |
| 三人代码风格不一 | 每端只改自己目录；公共层统一由邓昌兴改；提交前跑 `npm run lint` |
